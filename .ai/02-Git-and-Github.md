# 02 - Git and Github

این فایل برای نظم فنی ریپو، مدیریت نسخه، همکاری تیمی، و نحوه‌ی کار درست با Git و GitHub نوشته شده است. در Khatmax، Git فقط ابزار ذخیره‌ی تغییرات نیست؛ بخشی از سیستم توسعه و کنترل کیفیت پروژه است.

## هدف این بخش
- تغییرات باید قابل‌ردگیری باشند.
- هر change باید دلیل روشن داشته باشد.
- تیم و agent باید بتوانند تاریخچه‌ی پروژه را راحت دنبال کنند.
- ریپو باید هم‌زمان با توسعه‌ی محلی و بروزرسانی از upstream هماهنگ بماند.

## اصول کار با Git
- کار را روی branch جدا انجام بده.
- تغییرات را کوچک، مشخص و متمرکز نگه دار.
- از commitهای بزرگ و مبهم پرهیز کن.
- قبل از نهایی‌کردن، diff را بررسی کن.
- اگر بخشی از تغییر مربوط به task نیست، همان را دست‌نخورده بگذار.

## commit message
- commit message باید ساده و کوتاه باشد.
- پیام باید بگوید چه چیزی تغییر کرده، نه اینکه داستان کامل را بنویسد.
- اگر تغییر چند بخش دارد، commit را به بخش‌های منطقی تقسیم کن.
- از commitهای کلی مثل `update` یا `fix stuff` تا جای ممکن پرهیز کن.

## Pull Request
- هر تغییر مهم باید برای review آماده شود.
- PR باید توضیح بدهد چه چیزی تغییر کرده و چرا.
- اگر ریسک دارد، باید صریح گفته شود.
- review باید هم فنی باشد و هم روی اثر جانبی‌ها تمرکز کند.

## sync با upstream
- Khatmax باید با گیت اصلی پروژه هم‌راستا بماند.
- اگر upstream تغییر کرد، اثر آن را قبل از merge یا rebase بررسی کن.
- بروزرسانی از git اصلی باید منظم، قابل‌پیگیری و کم‌ریسک باشد.
- اگر اختلافی در ساختار یا API ایجاد شد، باید قبل از ادغام حل شود.

## قواعد مخصوص agent
- agent قبل از تغییر باید context ریپو را بررسی کند.
- agent فقط روی فایل‌هایی کار کند که واقعاً به task مربوط هستند.
- اگر تغییر به `src/`، `extensions/` یا `build/` مربوط است، اثر آن روی بقیه‌ی سیستم هم سنجیده شود.
- agent باید همیشه توضیح دهد چرا یک مسیر انتخاب شده است.
- agent نباید بدون دلیل فایل‌های نامرتبط را تغییر دهد.

## مدیریت نسخه
- نسخه باید ساده، شفاف و قابل‌اعتماد باشد.
- تاریخچه‌ی ریپو باید خوانا بماند.
- هر تغییر مهم باید قابل‌برگشت و قابل‌بررسی باشد.
- اگر نسخه یا ساختار release تغییر کند، باید در اسناد هم منعکس شود.

## قوانین عملی
- تغییرات را قبل از merge بررسی کن.
- فایل‌های generated را بی‌دلیل دستکاری نکن.
- هرجا لازم شد، هماهنگی با upstream را اولویت بده.
- اگر ابزار یا workflow جدید اضافه شد، این سند را هم به‌روز کن.

## نتیجه‌ی مورد انتظار
- تاریخچه‌ی تمیز
- همکاری شفاف
- هم‌راستایی با upstream
- آمادگی برای کار تیمی و کار agentها
