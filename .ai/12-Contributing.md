# 12 - Contributing

این سند برای نحوه‌ی مشارکت در Khatmax نوشته شده است. چون پروژه هم هسته‌ی VS Code را دارد و هم لایه‌های جدید AI-first، contribution باید دقیق، مرحله‌مند و قابل‌بررسی باشد.

## هدف
- کمک به همکاری تمیز و قابل‌اعتماد
- حفظ انسجام معماری
- جلوگیری از تغییرات بی‌جهت
- آماده‌کردن مسیر برای کار تیمی و agentی

## قواعد عمومی
- تغییر را کوچک نگه دار.
- فقط چیزی را عوض کن که به task مربوط است.
- اگر فایل نامرتبط تغییر کرده، آن را بازبینی کن.
- قبل از merge، اثر side effect را بررسی کن.

## روند پیشنهادی
- task را کامل بخوان.
- context فایل‌ها و dependencyها را پیدا کن.
- تغییر را در کوچک‌ترین سطح ممکن انجام بده.
- typecheck و validation مناسب را اجرا کن.
- summary شفاف بنویس.

## استاندارد برای agent
- agent باید قبل از تغییر، معماری و context را ببیند.
- agent نباید بدون دلیل لایه‌ها را دور بزند.
- agent باید در صورت ابهام، سوال یا هشدار بدهد.
- agent باید تغییرات را در راستای roadmap انجام دهد.

## code quality
- از تکرار غیرضروری پرهیز کن.
- naming باید واضح باشد.
- ساختار باید با الگوی پروژه هماهنگ باشد.
- اگر behavior جدیدی می‌آوری، تست یا validation هم در نظر بگیر.

## review
- PR باید کوچک و قابل‌بررسی باشد.
- توضیح change باید دلیل و اثر را بگوید.
- riskهای change باید واضح نوشته شوند.
- review باید روی correctness، architecture و regression تمرکز کند.

## مستندسازی
- اگر چیزی در workflow یا structure تغییر می‌کند، docs هم باید به‌روز شوند.
- اسناد Khatmax بخشی از محصول هستند، نه یک کار جانبی.

## نتیجه‌ی مطلوب
- همکاری شفاف
- تغییرات قابل‌ردگیری
- کد تمیزتر
- آماده برای تیم و AI
