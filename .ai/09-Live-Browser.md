# 09 - Live Browser

Live Browser یکی از بخش‌های کلیدی Khatmax برای دیدن نتیجه‌ی واقعی کار در مرورگر است. این بخش باید به کاربر و AI اجازه بدهد خروجی پروژه را در همان لحظه ببینند، بررسی کنند و در صورت نیاز اصلاح کنند.

## هدف
- نمایش زنده‌ی UI و رفتار برنامه
- کمک به تست و validation سریع
- اتصال preview به workflow توسعه
- امکان مشاهده‌ی اثر تغییرات بدون خروج از workspace

## نقش‌ها
- preview زنده‌ی front-end
- بررسی رفتار interaction
- مشاهده‌ی خطاها و warningها
- کمک به debugging و analysis
- ایجاد حلقه‌ی سریع بین تغییر و مشاهده

## چرا مهم است
- خیلی از مشکلات فقط در runtime دیده می‌شوند.
- برخی از تغییرات UI در کد خوب به نظر می‌رسند اما در عمل مشکل دارند.
- AI باید بتواند نتیجه‌ی کار خودش را ببیند.
- کاربر هم باید بتواند بدون جابه‌جایی بین ابزارها، خروجی را بررسی کند.

## ساختار عملکرد
- پروژه در workspace تغییر می‌کند.
- browser preview به‌صورت زنده به آن متصل می‌شود.
- تغییرات در runtime قابل‌مشاهده هستند.
- در صورت وجود خطا، سیستم باید وضعیت را واضح نشان دهد.

## ارتباط با AI
- AI می‌تواند preview را ببیند و تحلیل کند.
- AI می‌تواند بر اساس رفتار live تصمیم بگیرد.
- AI باید بتواند از browser برای validate کردن کار خودش استفاده کند.
- این بخش برای agent فقط نمایش نیست؛ ابزار تصمیم‌گیری هم هست.

## مواردی که باید دیده شوند
- layout
- responsiveness
- state transitions
- loading behavior
- errors
- empty states
- interaction issues

## UX مورد انتظار
- preview باید سریع و قابل‌اعتماد باشد.
- کاربر باید بفهمد چه چیزی live است و چه چیزی stale.
- کنترل‌ها باید ساده و قابل‌فهم باشند.
- بین editor و browser نباید فاصله‌ی زیادی احساس شود.

## نتیجه‌ی مطلوب
- مشاهده‌ی مستقیم اثر تغییرات
- validation سریع‌تر
- debug آسان‌تر
- هماهنگی بهتر بین AI، developer و runtime
