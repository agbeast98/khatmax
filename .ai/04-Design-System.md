# 04 - Design System

Design System در Khatmax فقط مجموعه‌ای از رنگ و component نیست؛ این سیستم باید تجربه‌ی کار با AI، شفافیت عملکرد، و حس کنترل را در سراسر محصول حفظ کند. چون محصول ما AI Workspace است، طراحی باید هم حرفه‌ای باشد و هم برای کاربر تازه‌کار ترسناک نباشد.

## هدف Design System
- ایجاد انسجام بین تمام surfaceها
- حفظ خوانایی و سادگی در محیطی پیچیده
- نشان دادن وضعیت AI به‌صورت روشن و قابل‌فهم
- پشتیبانی از تجربه‌ی حرفه‌ای و تجربه‌ی ساده در یک سیستم واحد

## اصول طراحی
- وضوح: کاربر باید بداند هر بخش چه کاری انجام می‌دهد.
- کنترل: هر رفتار AI باید قابل‌توقف، ویرایش یا بررسی باشد.
- انسجام: componentها و surfaceها باید یک زبان مشترک داشته باشند.
- اعتماد: UI باید حرفه‌ای، پایدار و پیش‌بینی‌پذیر باشد.
- سرعت ادراکی: کاربر باید سریع بفهمد الان در چه مرحله‌ای است.

## سطح‌های طراحی
- `App Shell`: ساختار اصلی اپ و تقسیم‌بندی محیط.
- `Workspace`: فضای مرکزی برای پروژه، AI و taskها.
- `Editor Surfaces`: ادیتور، فایل‌ها، diff و inspect.
- `Agent Surfaces`: timeline، status، reasoning و controls.
- `Runtime Surfaces`: preview، logs، browser و monitor.
- `System Surfaces`: auth، settings، provider config و admin tools.

## نمایش AI
- AI نباید به‌صورت یک باکس چت ساده دیده شود.
- AI باید در سطح workspace، task panel، timeline و runtime حضور داشته باشد.
- وضعیت AI باید قابل‌مشاهده باشد: در حال اجرا، منتظر تایید، خطا، تکمیل‌شده، متوقف‌شده.
- کاربر باید دلیل تصمیم‌ها را هم ببیند، نه فقط خروجی نهایی را.

## states
- `default`
- `hover`
- `focus`
- `active`
- `disabled`
- `loading`
- `success`
- `warning`
- `error`

## component strategy
- از الگوهای تکراری و ناسازگار پرهیز کن.
- component جدید باید با pattern موجود هماهنگ باشد.
- اگر pattern جدید لازم است، باید قابل‌استفاده در چند جای دیگر هم باشد.
- UI نباید فقط زیبا باشد؛ باید قابل‌خواندن و قابل‌تعامل باشد.

## accessibility
- کنتراست باید مناسب باشد.
- keyboard navigation باید کامل باشد.
- stateهای مهم باید برای screen reader هم قابل‌تشخیص باشند.
- تعاملات AI نباید کاربر را از کنترل خارج کند.

## motion و feedback
- حرکت‌ها باید معنی‌دار باشند، نه تزئینی.
- transition باید برای فهم تغییر state کمک کند.
- statusهای AI باید feedback واضح داشته باشند.
- از motion زیاد و شلوغ پرهیز شود.

## evolution
- Design System باید همراه با رشد محصول تکامل پیدا کند.
- هر surface جدید باید به این سیستم برگردد.
- اگر UI جدیدی اضافه شد، باید زبان موجود را تقویت کند نه اینکه آن را بشکند.

## نتیجه‌ی مطلوب
- تجربه‌ی یکپارچه
- حس حرفه‌ای بودن
- شفافیت رفتار AI
- سهولت استفاده برای مبتدی و حرفه‌ای
