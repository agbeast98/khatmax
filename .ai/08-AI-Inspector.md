# 08 - AI Inspector

AI Inspector نقش ناظر و تحلیل‌گر را در Khatmax دارد. این بخش برای بررسی خروجی agentها، تشخیص ریسک‌ها، پیدا کردن ناسازگاری‌ها و کمک به تصمیم‌گیری بهتر طراحی می‌شود. اگر agent انجام‌دهنده است، inspector بازبین و محافظ کیفیت است.

## هدف
- بررسی صحت خروجی AI
- پیدا کردن خطا و ریسک قبل از اثر واقعی
- کمک به انسان برای فهمیدن دلیل تصمیم‌ها
- جلوگیری از اجرای کورکورانه‌ی تغییرات

## وظایف اصلی
- بررسی diffها
- بررسی ساختار و compatibility
- بررسی منطق تصمیم‌گیری agent
- بررسی اثر جانبی روی runtime و UI
- تشخیص جاافتادگی تست‌ها

## انواع inspection
- `Static Inspection`: بررسی کد، ساختار و تغییرات بدون اجرا.
- `Runtime Inspection`: بررسی رفتار واقعی در زمان اجرا.
- `Workflow Inspection`: بررسی ترتیب و منطق کار agent.
- `Risk Inspection`: بررسی اینکه تغییر چه چیزی را ممکن است بشکند.

## خروجی inspector
- باید کوتاه، دقیق و عملی باشد.
- باید بگوید مشکل کجاست و چرا مهم است.
- باید پیشنهاد بدهد چه چیزی اصلاح شود.
- باید بین issue واقعی و حدس تفکیک قائل شود.

## رابطه با agent system
- inspector نباید فقط بعد از شکست وارد شود.
- می‌تواند قبل، حین و بعد از اجرا نقش داشته باشد.
- اگر تصمیمی حساس است، inspector باید آن را flag کند.
- اگر خروجی به context کافی متکی نیست، inspector باید هشدار بدهد.

## relation با user
- کاربر باید بتواند نتیجه‌ی بررسی را ببیند.
- کاربر باید بداند چه چیزی تایید شده و چه چیزی مشکوک است.
- کاربر باید در صورت نیاز بتواند از نتیجه عبور کند یا آن را اصلاح کند.

## کیفیت بررسی
- بررسی نباید سطحی باشد.
- نباید فقط به syntax نگاه کند.
- باید رفتار، architecture و product impact را هم بسنجد.
- باید کمک کند تغییرات سریع‌تر ولی امن‌تر انجام شوند.

## نتیجه‌ی مطلوب

- اعتماد بیشتر
- خطای کمتر
- درک بهتر از کار AI
